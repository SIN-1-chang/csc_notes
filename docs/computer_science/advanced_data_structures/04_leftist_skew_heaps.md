## 1 可合并堆的引入与左偏堆定义 (Introduction and Leftist Heaps)

### 1.1 二叉堆回顾与合并操作的瓶颈

在基础数据结构课程中，我们学习了基于数组实现的**二叉堆**（Binary Heap，一种优先队列 Priority Queue）。任何堆结构都由两条核心性质界定：**结构性质**（Structure Property）与**序性质**（Order Property）。对于经典二叉最小堆（Min-Heap，本章无特殊说明均默认最小堆）：

1. **结构性质**：是一棵**完全二叉树**（Complete binary tree），因此树高严格满足 $h = \lfloor\log_2 N\rfloor = O(\log N)$，且可直接紧凑存储在数组中（无需左右孩子指针）。
2. **序性质**：任意节点的键值大于等于其父节点的键值（`u->key >= u->parent->key`），故根节点始终存放全局最小元素。

二叉堆各基本操作的时间复杂度回顾如下：

- `FindMin`：直接返回数组首元素，$O(1)$；
- `Insert` / `DeleteMin`：在末尾插入后上滤（Percolate up），或用末尾元素覆盖根后下滤（Percolate down），均为 $O(\log N)$；
- `DecreaseKey` / `Delete`（**前提：已知目标元素在堆中的位置指针或通过 `pos[]` 映射数组定位**）：修改键值后上滤或下滤，均为 $O(\log N)$；
- `BuildHeap`（线性建堆）：将 $N$ 个元素任意放入数组，从倒数第二层最后一个内部节点开始逆序逐个执行 `PercolateDown`。由于高度至少为 $j$ 的节点至多有 $\lceil N / 2^{j+1} \rceil$ 个，总下滤步数为 $O\left(N \sum_{j=1}^{\log N} j \cdot 2^{-j}\right) = O(N)$。

**问题与挑战（Discussion 5）：如果使用原始的数组二叉堆，合并（Merge）两个堆最快需要多少时间？**
由于两个完全二叉树合并后仍需保持完全二叉树形态并维护紧凑数组，我们只能将两个数组拼接后重新调用 `BuildHeap`（耗时 $\Theta(N_1 + N_2) = \Theta(N)$），或者将较小堆的元素逐一插入较大堆（耗时 $O(\min(N_1, N_2)\log(N_1 + N_2))$）。为了将 **`Merge` 操作加速到 $O(\log N)$**，我们必须放弃“完全二叉树”与数组存储，转而设计基于指针的树形**可合并堆**（Mergeable Heaps）。

### 1.2 零路径长 (`Npl`) 与左偏堆的性质

**左偏堆**（Leftist Heap，又称**左式堆**或**左偏树** Leftist Tree）保持了与普通二叉堆完全相同的**堆序性质**（Order Property），但在**结构性质**上做出了激进的改变：它是一棵**高度不平衡（Unbalanced）的二叉树**，故意让树向左侧深度倾斜，从而使右侧路径变得极短！

**定义 1.1（零路径长 Null Path Length, `Npl`）**：
任意节点 $X$ 的**零路径长** `Npl(X)` 定义为从 $X$ 出发到达一个**不满节点（即没有两个孩子的节点，度数为 0 或 1）**的最短路径长度（按边数计）。规定空节点的零路径长为：

$$\text{Npl}(\text{NULL}) = -1$$

由此可知，任何具有 0 个或 1 个孩子的节点（包括所有叶节点）其 $\text{Npl} = 0$；对于任意节点 $X$，其零路径长满足自底向上的递推关系：

$$\text{Npl}(X) = \min\big\{\text{Npl}(X.\text{Left}), \ \text{Npl}(X.\text{Right})\big\} + 1$$

!!! warning "符号约定辨析：课程组 PPT 约定 vs. 老师手写板书约定"
    - **课程组 PPT 与 Weiss 教材约定（考试做题默认标准）**：定义 $\text{Npl}(\text{NULL}) = -1$，因此叶节点及单孩子节点的 $\text{Npl} = 0$。此時 $\text{Npl}(X)$ 代表从 $X$ 到最近不满节点的**边数**。
    - **老师手写板书（`ADS26W4.pdf`）约定**：板书中将空节点定义为 $\text{npl}(\text{null}) = 0$，因此叶节点的 $\text{npl} = 1$。此时板书上的 $\text{npl}(X) = \text{Npl}_{\text{PPT}}(X) + 1$，恰好等于从 $X$ 沿右路径走到 `null` 所经过的**非空节点个数**！两套定义在逻辑和代码判断 `npl(Left) < npl(Right)` 上完全等价，做卷面填空题时请认准 PPT 标准（$\text{Npl}(\text{NULL}) = -1$）。

**定义 1.2（左偏堆性质 Leftist Heap Property）**：
在左偏堆中，对于堆中的**每一个节点 $X$**，其左孩子的零路径长都至少与右孩子的零路径长一样大：

$$\text{Npl}(X.\text{Left}) \ge \text{Npl}(X.\text{Right}), \qquad \forall X$$

- **判别陷阱**：判断一棵二叉树是否满足左偏性质时，不仅要看整棵树的根，必须检查**每一个内部节点**是否都满足左孩子 $\text{Npl} \ge$ 右孩子 $\text{Npl}$！
- **直接推论**：在满足左偏性质的树中，由于 $\min\{\text{Npl}(X.\text{Left}), \text{Npl}(X.\text{Right})\} = \text{Npl}(X.\text{Right})$，任意节点 $X$ 的零路径长直接由其**右孩子**决定：
  $$\text{Npl}(X) = \text{Npl}(X.\text{Right}) + 1$$
  设从节点 $X$ 出发一路沿着右孩子指针走到 `NULL` 的路径为 $X$ 的**右路径**（Right path）。若右路径上共有 $r$ 个非空节点，则根节点 $X$ 的零路径长恰为 $\text{Npl}(X) = r - 1$（即右路径的边数）。

### 1.3 右路径长度定理与对数上界证明

为什么要把树设计成向左侧倾斜？下面的核心定理揭示了左偏性质的威力：

**定理 1.1（左偏树节点数下界定理）**：若一棵左偏树的**右路径（Right path）上有 $r$ 个节点**，则这棵左偏树**至少包含 $2^r - 1$ 个节点**。

<details markdown="1">
<summary>点击展开：定理 1.1 的数学归纳法严格证明（板书与讲义双视角）</summary>

**证明（对右路径上的节点个数 $r$ 进行数学归纳）**：

1. **归纳基（Base Case）**：
   当 $r = 0$（空树）时，节点数为 $0 = 2^0 - 1$；当 $r = 1$ 时，树至少包含根节点自身，节点数 $\ge 1 = 2^1 - 1$，结论显然成立。
2. **归纳假设（Inductive Hypothesis）**：
   假设对于所有右路径节点数不超过 $k \ (k \ge 1)$ 的左偏树，其总节点数均至少为 $2^k - 1$。
3. **归纳步（Inductive Step）**：
   考察一棵右路径上有 $r = k + 1$ 个节点的左偏树 $T$（根节点为 $u$，左子树为 $A$，右子树为 $B$）：
   - 由于整棵树 $T$ 的右路径上有 $k + 1$ 个节点，去掉根节点 $u$ 后，其**右子树 $B$ 的右路径上恰好有 $k$ 个节点**（即 $\text{Npl}(B) = k - 1$）；
   - 根据左偏堆性质 $\text{Npl}(A) \ge \text{Npl}(B) = k - 1$，可知**左子树 $A$ 的右路径上至少也有 $k$ 个节点**！
   - 对左子树 $A$（右路径 $\ge k$ 个节点）和右子树 $B$（右路径 $= k$ 个节点）分别应用归纳假设，可知 $\vert{}A\vert{} \ge 2^k - 1$ 且 $\vert{}B\vert{} \ge 2^k - 1$。
   - 因此，整棵树 $T$ 的总节点数满足：
     $$\vert{}T\vert{} = 1 + \vert{}A\vert{} + \vert{}B\vert{} \ge 1 + (2^k - 1) + (2^k - 1) = 2^{k+1} - 1 = 2^r - 1$$
   由数学归纳法，定理对任意整数 $r \ge 0$ 均成立。（注：等号仅当该左偏树是一棵高度为 $r - 1$ 的完美满二叉树时取到）。

</details>

**重要推论（Discussion 6：右路径长度的对数上界）**：
对于一棵含有 $N$ 个节点的左偏树，设其右路径上有 $r$ 个节点。由定理 1.1 知：

$$N \ge 2^r - 1 \implies 2^r \le N + 1 \implies r \le \lfloor\log_2(N + 1)\rfloor = O(\log N)$$

**这对我们意味着什么？**
因为二叉堆不支持查找任意元素（无需访问左子树深处的节点），而左偏树的**右路径长度永远不超过 $\lfloor\log_2(N+1)\rfloor$**，所以我们只需**将所有核心操作（`Merge`、`Insert`、`DeleteMin`）的全部工作都限制在极短的右路径上进行**，即可轻松实现 $O(\log N)$ 的最坏时间复杂度！

## 2 左偏堆的核心操作与实现 (Operations on Leftist Heaps)

在左偏堆中，**合并（`Merge`）是最核心的基石操作**：
- **插入（`Insert`）**：仅是合并操作的特例——将待插入元素视为一个单节点左偏堆，与原堆执行 `Merge`；
- **删除最小值（`DeleteMin`）**：直接删去根节点（最小元），然后将根节点的左子树和右子树执行 `Merge`。

### 2.1 节点声明与递归合并算法 (`Merge` - Recursive Version)

左偏堆的节点结构体声明如下（相比普通二叉树，仅多了一个 `int Npl` 字段）：

```c
struct TreeNode {
    ElementType   Element;
    PriorityQueue Left;
    PriorityQueue Right;
    int           Npl;
};
```

**递归合并两个左偏堆 $H_1$ 和 $H_2$ 的三步逻辑**（假设均非空，且已比较根节点使得 $H_1\text{->Element} \le H_2\text{->Element}$）：

1. **Step 1（递归合并右子树）**：保持 $H_1$ 的左子树丝毫不动，递归调用 `Merge(H1->Right, H2)`，将 $H_1$ 的右子树与 $H_2$ 合并；
2. **Step 2（挂接新右子树）**：将合并返回的新堆挂接为 $H_1$ 的右孩子（`H1->Right = Merge(H1->Right, H2)`）；
3. **Step 3（维护左偏性质与更新 `Npl`）**：若此时 $H_1$ 违反了左偏性质（即 `H1->Left->Npl < H1->Right->Npl`，或 `H1->Left == NULL`），则交换 $H_1$ 的左、右孩子（`SwapChildren(H1)`），最后更新 $H_1$ 的零路径长 `H1->Npl = H1->Right->Npl + 1`。

```c
PriorityQueue Merge(PriorityQueue H1, PriorityQueue H2) {
    if (H1 == NULL) return H2;
    if (H2 == NULL) return H1;
    if (H1->Element < H2->Element)
        return Merge1(H1, H2);
    else
        return Merge1(H2, H1);
}

static PriorityQueue Merge1(PriorityQueue H1, PriorityQueue H2) {
    if (H1->Left == NULL)     /* single node: H1 没有左孩子，由左偏性质知必无右孩子 */
        H1->Left = H2;        /* 直接将 H2 挂在左边；H1->Right 仍为 NULL，H1->Npl 仍为 0 */
    else {
        H1->Right = Merge(H1->Right, H2);           /* Step 1 & 2: 递归合并右子树 */
        if (H1->Left->Npl < H1->Right->Npl)
            SwapChildren(H1);                       /* Step 3: 违反左偏性质则交换左右孩子 */
        H1->Npl = H1->Right->Npl + 1;               /* 更新当前根的 Npl */
    }
    return H1;
}
```

- **时间复杂度分析**：每次递归调用都会沿着 $H_1$ 或 $H_2$ 的右路径向下推进一步，而每层回溯只做常数次指针交换与加法。因此递归总层数至多为两堆右路径长度之和 $\le \lfloor\log_2(N_1+1)\rfloor + \lfloor\log_2(N_2+1)\rfloor$，**最坏时间复杂度严格为 $T_p = O(\log N)$**。
- **课堂思考（Slide 6）：如果漏写了 `H1->Npl = H1->Right->Npl + 1`（不更新 `Npl`）会发生什么？**
  如果不再更新 `Npl`，所有节点的 `Npl` 将永远停留在初始单节点时的 $0$，导致条件 `H1->Left->Npl < H1->Right->Npl` 永远为假（除了左孩子为空时），算法将不再交换左右孩子，左偏堆彻底退化为普通偏斜二叉搜索/堆结构，右路径长度失控至 $O(N)$，合并时间退化为 $O(N)$！

### 2.2 迭代合并算法 (`Merge` - Iterative Version) 与图解追踪

将上述递归过程展开，即可得到直观的**两步迭代合并法**（手工画图做题最推荐的方法）：

1. **Step 1（右路径归并排序）**：将 $H_1$ 和 $H_2$ 的两条**右路径**（Right paths）抽出来，在不改变各节点原有左子树的前提下，按节点键值从小到大归并连接成一条新的右路径；
2. **Step 2（自底向上回溯交换与更新 `Npl`）**：从新右路径的最底端节点开始，沿着右路径向上逐个检查：若某节点的左孩子 `Npl` 小于右孩子 `Npl`，则交换其左、右孩子，并更新该节点的 `Npl` 为新右孩子的 `Npl + 1`。

**经典实例追踪（PPT Slides 5 & 7：合并 $H_1$ 与 $H_2$）**：
- **输入堆 $H_1$**：右路径为 `3 -> 8 -> 17 -> 26`（其中 `3` 的左子树根为 `10`，`8` 的左孩子为 `17` 但 `8` 无右孩子，严格来说 `3` 的右路径是 `3 -> 8`：`3` 的左孩子 `10` [$\text{Npl}=1$]，右孩子 `8` [$\text{Npl}=0$，仅有左孩子 `17` 挂左孩子 `26`]）；
- **输入堆 $H_2$**：右路径为 `6 -> 7 -> 18`（其中 `6` 的左孩子为 `12` [$\text{Npl}=1$]，`7` 的左孩子为 `37` [$\text{Npl}=0$]，右孩子为 `18` [$\text{Npl}=0$]）。
- **合并过程**：
  1. **归并两条右路径**（`3 -> 8` 与 `6 -> 7 -> 18`）：按大小排序拼成新右路径 `3 -> 6 -> 7 -> 8 -> 18`（最后一个节点 `18` 成为 `8` 的右孩子，而 `8` 原有的左孩子 `17 -> 26` 保持在 `8` 的左侧不变）；
  2. **自底向上检查并更新 `Npl`**：
     - 节点 `8`：左孩子 `17`（$\text{Npl}=0$），右孩子 `18`（$\text{Npl}=0$），左 $\ge$ 右无需交换，$\text{Npl}(8)$ 更新为 $0 + 1 = 1$；
     - 节点 `7`：左孩子 `37`（$\text{Npl}=0$）$<$ 新右孩子 `8`（$\text{Npl}=1$），**违反左偏性质，在节点 `7` 处交换左右孩子**（`8` 变左孩子，`37` 变右孩子），$\text{Npl}(7)$ 更新为 $\text{Npl}(37) + 1 = 1$；
     - 节点 `6`：左孩子 `12`（$\text{Npl}=1$）$\ge$ 右孩子 `7`（$\text{Npl}=1$），无需交换，$\text{Npl}(6)$ 更新为 $1 + 1 = 2$；
     - 根节点 `3`：左孩子 `10`（$\text{Npl}=1$）$<$ 新右孩子 `6`（$\text{Npl}=2$），**违反左偏性质，在根节点 `3` 处交换左右孩子**（`6` 变左孩子，`10` 变右孩子），$\text{Npl}(3)$ 更新为 $\text{Npl}(10) + 1 = 2$。合并完成！

### 2.3 任意给定节点的删除 (`Delete`) 与降键 (`DecreaseKey`)

在老师的手写板书（`ADS26W4.pdf` Pages 4–5）与讲义（§4.1.4）中，特别补充了左偏堆**删除任意给定位置节点 $u$**（以及降低节点 $u$ 的键值 `DecreaseKey`）的算法：

1. **拆分与合并框架**：
   设要删除堆 $H$ 中的内部节点 $u$（其左、右子树分别为 $A, B$）。我们先将整棵以 $u$ 为根的子树从其父节点 $u_1$ 处摘下（位置替换为 `NULL`），对剩余的堆 $H'$ 向上修复左偏性质与 `Npl`；然后删去节点 $u$，最后执行两次 `Merge`：将 $A$、$B$ 与修复后的 $H'$ 合并（`H = Merge(H', Merge(A, B))`）。
2. **从父节点 $u_1$ 向上回溯修复 $H'$ 的两类情况（板书推导）**：
   设从 $u$ 的祖先链 $u_1, u_2, \dots$ 依次向上检查。在当前祖先 $u_i$ 处，记刚被修改（`Npl` 减小）的那棵子树为 $u_{i-1}$，另一侧未变的兄弟子树为 $v$：
   - **Case 1（$u_{i-1}$ 是 $u_i$ 的右孩子）**：由于原本就有 $\text{Npl}(v) \ge \text{Npl}_{\text{old}}(u_{i-1})$，现在右孩子 $u_{i-1}$ 的 `Npl` 减小了，左孩子 $v$ 的 `Npl` 依然严格大于右孩子 $u_{i-1}$，**无需交换左右孩子**，直接将 $\text{Npl}(u_i)$ 更新为 $\text{Npl}(u_{i-1}) + 1$ 并继续向上检查 $u_{i+1}$；
   - **Case 2（$u_{i-1}$ 是 $u_i$ 的左孩子）**：左孩子 $u_{i-1}$ 的 `Npl` 减小后，比较 $\text{Npl}(u_{i-1})$ 与右孩子 $\text{Npl}(v)$：
     - 若 $\text{Npl}(u_{i-1}) < \text{Npl}(v)$：**交换 $u_{i-1}$ 与 $v$**（使 $u_{i-1}$ 换到右侧），并将 $\text{Npl}(u_i)$ 更新为 $\text{Npl}(u_{i-1}) + 1$，继续向上检查 $u_{i+1}$；
     - 若 $\text{Npl}(u_{i-1}) \ge \text{Npl}(v)$：此时左偏性质未破坏，且右孩子 $v$ 的 `Npl` 没变，故 **$\text{Npl}(u_i) = \text{Npl}(v) + 1$ 与修改前完全相同！直接 `break` 终止向上回溯**（更高层祖先的 `Npl` 均不会改变）！
3. **为什么向上修复至多访问 $O(\log N)$ 个祖先？**
   观察上述 Case 1 和 Case 2 的继续向上分支：只要修复没有在 $u_i$ 处 `break` 停止，而是继续向上传递到了父节点 $u_{i+1}$，那么在 $u_i$ 处理完毕后，**来自下层的子树 $u_{i-1}$ 必然处于 $u_i$ 的右孩子位置**（Case 1 本来就在右边；Case 2 只有交换到右边后才会继续向上）！因此，整条向上回溯的路径在修复完成后完全变成了某棵左偏树的**一条右路径**，根据定理 1.1，其长度绝不超过 $\lfloor\log_2(N+1)\rfloor = O(\log N)$！

## 3 斜堆 (Skew Heaps)

### 3.1 斜堆的设计思想与合并规则

**斜堆**（Skew Heap，又称自调节堆 Self-adjusting heap）是左偏堆的极简版本，它与左偏堆的关系正如 **Splay 树与 AVL 树的关系**：

- **两大优势（Slide 10 Note）**：
  1. **无需额外空间（No extra space）**：节点结构体中彻底去掉了 `int Npl` 字段，节省内存；
  2. **无需条件判断（No tests）**：在合并过程中，不再测试左右孩子的零路径长大小，而是采用**无条件交换**策略。
- **目标复杂度**：斜堆不保证单次操作最坏 $O(\log N)$（单次最坏可能为 $\Theta(N)$），但保证**任意连续 $M$ 次操作的总耗时至多为 $O(M \log N)$**（即单次操作的摊还时间为 $T_{\text{amortized}} = O(\log N)$）。

**斜堆的合并规则（Skew Heap `Merge` Rule）**：
斜堆的合并流程与左偏堆完全相同，唯一的区别在于：**在沿着归并后的右路径处理时，无条件交换路径上每一个节点的左、右孩子，唯一的例外是右路径上键值最大的那个末端节点不交换其左右孩子**（*"Always swap the left and right children except that the largest of all the nodes on the right paths does not have its children swapped"*）。

- **为什么末端最大节点不交换孩子？（Slide 8 气泡说明）**：
  这并不是一个需要专门写 `if` 特殊处理的规则，而是**递归算法到达基准情形（Base case）时的自然停止（Natural stop in the recursions）**！当其中一个堆为空（`H2 == NULL`）时，递归直接 `return H1`，此时处于右路径最末端的那个节点（及其原有的左孩子）作为整体直接返回，自然没有进入交换步骤。

```c
/* 斜堆的递归合并实现（对比左偏堆：无 Npl，无 if 判断，每次必交换） */
PriorityQueue SkewMerge(PriorityQueue H1, PriorityQueue H2) {
    if (H1 == NULL) return H2;
    if (H2 == NULL) return H1;
    if (H1->Element > H2->Element)
        Swap(H1, H2); /* 确保 H1 的根键值较小 */
    
    /* 若 H1 右孩子为空（即 H1 已是右路径末端且 H2 全大于它），但注意标准递归写法： */
    PriorityQueue temp = H1->Right;
    H1->Right = H1->Left;               /* 无条件将原左孩子换到右边 */
    H1->Left = SkewMerge(temp, H2);     /* 递归合并原右子树与 H2，并直接挂到左边！ */
    return H1;
}
```

*(注：在课堂 PPT 的约定中，若到达右路径最后一个节点时另一侧已为空，该末端节点自身不执行交换；在迭代版中，只需将两条右路径排序归并后，对除最后一个节点外的所有右路径节点逐个交换左右孩子即可，最终整条归并路径会变成新堆的左路径)。*

!!! note "开放问题（Open Problem, Slide 10）"
    精确确定左偏堆与斜堆在随机插入/删除操作序列下的**期望右路径长度（Expected right path length）**，在理论计算机科学中至今仍是一个尚未完全解决的开放问题（Open problem）。

### 3.2 斜堆的摊还分析 ($T_{\text{amortized}} = O(\log N)$ 严格证明)

由于斜堆不维护 `Npl`，树形在最坏情况下可能退化为右斜链，我们需要使用第一章的**势能法（Potential Method）**证明其 `Merge` 操作（进而 `Insert` 和 `DeleteMin`）的摊还时间复杂度为 $O(\log N)$。

**1. 重节点（Heavy Node）与轻节点（Light Node）的定义**

记 $\text{size}(p)$ 为以节点 $p$ 为根的子树所包含的节点总数（**包含 $p$ 自身**）。

**定义 3.1（重节点与轻节点）**：
称节点 $p$ 是**重的（Heavy node）**，如果 $p$ 的**右子树**节点个数至少占 $p$ 的所有后代节点总数的一半：

$$
p \text{ is heavy} \iff \text{size}(p.\text{right}) \ge \frac{1}{2}\text{size}(p)
$$

否则（即 $\text{size}(p.\text{right}) < \frac{1}{2}\text{size}(p)$），称节点 $p$ 是**轻的（Light node）**。

**引理 3.1（右路径轻节点个数的对数上界）**：
在任意一棵含有 $N$ 个节点的斜堆中，其**右路径（Right path）上的轻节点个数 $l$ 至多为 $\lfloor\log_2(N + 1)\rfloor = O(\log N)$**（等价表述：右路径上有 $l$ 个轻节点的斜堆至少有 $2^l - 1$ 个节点）。

*证明*：每当沿着右路径经过一个**轻节点** $p$ 进入其右孩子时，根据轻节点的定义，右子树的节点数严格小于 $p$ 的子树节点数的一半（$\text{size}(p.\text{right}) \le \frac{1}{2}(\text{size}(p) - 1)$）。由于整棵树总共只有 $N$ 个节点，节点数最多只能减半 $\lfloor\log_2(N + 1)\rfloor$ 次，故右路径上的轻节点个数必满足 $l \le \lfloor\log_2(N + 1)\rfloor = O(\log N)$。

**2. 势能函数构造与 `Merge` 摊还代价推导（PPT Slides 11–12 & 板书 `W4` Pages 5–6）**

定义斜堆 $D_i$ 的**势能函数** $\Phi(D_i)$ 为**堆中所有重节点（Heavy nodes）的总个数**：

$$
\Phi(D_i) = \text{number of heavy nodes in } D_i
$$

显然，空堆的势能为 $\Phi_0 = 0$，且任意时刻 $\Phi(D_i) \ge 0$。现在考察合并两个斜堆 $H_1$（含 $N_1$ 个节点）和 $H_2$（含 $N_2$ 个节点，记 $N = N_1 + N_2$）得到新堆 $H_3$ 的过程：

1. **合并前的状态与最坏实际代价 $T_{\text{worst}}$**：
   设合并前 $H_i \ (i = 1, 2)$ 的右路径上有 $l_i$ 个轻节点和 $h_i$ 个重节点，且不在两条右路径上的其余所有重节点总数为 $h$。
   - 合并前的初始总势能为：
     $$
     \Phi_0 = h_1 + h_2 + h
     $$
   - 合并操作只需遍历两条右路径上的所有节点，故最坏实际耗时为：
     $$
     T_{\text{worst}} = l_1 + h_1 + l_2 + h_2
     $$
2. **合并后的状态变化（两条核心性质）**：
   - **性质 A（非右路径节点状态不变）**：只有在初始右路径上的节点，其子树节点总数和左右孩子位置才会在合并中发生改变；不在初始右路径上的任何节点，其左右子树在合并前后原封不动，因此那 $h$ 个非右路径重节点在合并后依然是重节点！
   - **性质 B（右路径上的重节点必定全部变轻！）**：对于初始右路径上的每一个**重节点** $p$（原本右子树 $\ge \frac{1}{2}\text{size}_{\text{old}}(p)$，从而左子树 $< \frac{1}{2}\text{size}_{\text{old}}(p)$），在合并时：
     ① 它的左、右孩子被交换（原本较小的左子树换到了右边，成为新右子树）；
     ② 新合并进来的其他节点又被挂接到了它的新左子树上（使 $\text{size}_{\text{new}}(p) \ge \text{size}_{\text{old}}(p)$ 进一步变大）。
     因此，交换后它的新右子树大小满足 $\text{size}_{\text{new}}(p.\text{right}) = \text{size}_{\text{old}}(p.\text{left}) < \frac{1}{2}\text{size}_{\text{old}}(p) \le \frac{1}{2}\text{size}_{\text{new}}(p)$，即**右路径上的全部 $h_1 + h_2$ 个重节点在合并后百分之百变成了轻节点**！（注：右路径最末端的那个不交换节点原本就没有右孩子，本来就是轻节点，绝不可能是重节点）。
   - 同时，原本右路径上的 $l_1 + l_2$ 个轻节点在交换孩子后，至多全部变成重节点。
3. **计算合并后的势能 $\Phi_N$ 与摊还代价 $T_{\text{amortized}}$**：
   由上述两条性质，合并后新堆中的重节点总数至多为：
   $$
   \Phi_N \le l_1 + l_2 + h
   $$
   因此势能变化量为 $\Delta\Phi = \Phi_N - \Phi_0 \le (l_1 + l_2 + h) - (h_1 + h_2 + h) = l_1 + l_2 - h_1 - h_2$。代入摊还代价公式，**昂贵的重节点项 $h_1 + h_2$ 被完美抵消**：
   $$
   \begin{aligned}
   T_{\text{amortized}} &= T_{\text{worst}} + \Phi_N - \Phi_0 \\
   &\le (l_1 + h_1 + l_2 + h_2) + (l_1 + l_2 - h_1 - h_2) \\
   &= 2(l_1 + l_2)
   \end{aligned}
   $$
   由引理 3.1 知 $l_1 \le \log_2(N_1 + 1)$ 且 $l_2 \le \log_2(N_2 + 1)$，故 $2(l_1 + l_2) = O(\log N)$，证毕！

## 4 Chapter 4 核心习题精解 (Selected Exercises)

<details markdown="1">
<summary>Exercise 4.1 & 4.2: Root NPL Properties & Maximum Root NPL Increase After Merge（根 NPL 性质与合并后根 NPL 增幅反例）</summary>

**Problem Statement:**
- **Ex 4.1**: 非空左偏堆根节点的 $\text{Npl}$ 是否恒等于其右路径的长度（长度按边数计算）？
- **Ex 4.2**: 两棵左偏堆的根 $\text{Npl}$ 不相同，合并后的新根 $\text{Npl}$ 是否一定不超过两者的较大值？是否一定不超过两者的较小值加一？请用同一个反例回答。

---

**解答与解析：**

**1. 根节点的 $\text{Npl}$ 与右路径边数关系（Exercise 4.1）**：
**恒相等**。因为根据左偏性质，对任意节点 $x$ 恒有 $\text{Npl}(x.\text{left}) \ge \text{Npl}(x.\text{right})$，故递推式简化为 $\text{Npl}(x) = \text{Npl}(x.\text{right}) + 1$。设非空左偏堆的右路径共有 $k$ 条边（即 $k+1$ 个节点，末端第 $k+1$ 个节点的右孩子为 `NULL`），则末端节点的 $\text{Npl} = \text{Npl}(\text{NULL}) + 1 = 0$，沿着右路径向上累加 $k$ 条边，根节点的 $\text{Npl}$ 恰好等于 $k$。

---

**2. 合并后根 $\text{Npl}$ 增长幅度的经典反例（Exercise 4.2，高频判断题陷阱）**：
两个说法**均错误**！（即合并后的根 $\text{Npl}$ 既可能超过原两堆根 $\text{Npl}$ 的较大值，也可能超过较小值加一）。
**统一反例构造**：
- **左偏堆 $A$（单节点堆）**：仅含根节点 `1`，其 $\text{Npl}(A) = 0$；
- **左偏堆 $B$（含 6 个节点）**：根为 `2`，左子树为满二叉树 `3(4, 5)`（$\text{Npl}(3) = 1$），右子树为链 `6(7, _)`（即 `6` 的左孩子为 `7`、右孩子为空，故 $\text{Npl}(6) = 0$）。此时根 `2` 的左孩子 $\text{Npl}=1 \ge$ 右孩子 $\text{Npl}=0$，合法且 **$\text{Npl}(B) = 0 + 1 = 1$**。
- **执行 `Merge(A, B)`**：
  由于 $A$ 是单节点 `1` 且键值最小，原堆 $B$ 直接挂接在 `1` 的右侧（随后交换到左侧）；或者反过来，若令堆 $A$ 为单节点 **`7`**（$\text{Npl}(A) = 0$），堆 $B$ 为含 6 个节点的左偏堆：根为 `1`，左子树为满二叉树 `2(4, 5)`（$\text{Npl}(2) = 1$），右子树为 `3(6, _)`（`3` 只有左孩子 `6`，$\text{Npl}(3) = 0$），故 **$\text{Npl}(B) = 1$**。
  现将 $A$（单节点 `7`）与 $B$ 合并：
  `7` 沿着 $B$ 的右路径 `1 -> 3` 向下合并，成为 `3` 的右孩子！此时节点 `3` 同时拥有了左孩子 `6` 和右孩子 `7`，变成了满二叉树（$\text{Npl}(3)$ 从 $0$ 跃升为 $1$），进而整棵合并后的树变成了一棵包含 $7$ 个节点的 3 层完美满二叉树，**合并后新根 `1` 的 $\text{Npl}$ 变成了 $2$**！
  对比合并前的 $\text{Npl}(A) = 0$ 与 $\text{Npl}(B) = 1$：合并后的 $\text{Npl} = 2$，既大于较大值 $\max(0, 1) = 1$，也大于较小值加一 $\min(0, 1) + 1 = 1$！

</details>

<details markdown="1">
<summary>Exercise 4.3 & 4.4: Skew Heap Bad Potential Counterexample & Sequential Insertion（斜堆错误势函数反例与顺序插入完美二叉树性质）</summary>

**Problem Statement:**
- **Ex 4.3**: 构造由两棵非空斜堆组成的输入，使一次合并需要线性时间 $\Theta(n)$，并且“右孩子总数”这一候选势能函数在合并过程中完全不下降（从而证明不能用“右孩子总数”作为斜堆的势函数）。
- **Ex 4.4**: 设 $k \ge 1$，从空堆开始按键值从小到大依次插入 $1, 2, \dots, 2^k - 1$。判断：① 对左偏堆执行上述操作，结果是否是一棵有 $k$ 层的完美满二叉树？② 对斜堆执行上述操作，结果是否也是一棵有 $k$ 层的完美满二叉树？

---

**解答与解析：**

**1. 为什么“右孩子总数”不能作为斜堆的势能函数？（Exercise 4.3）**：
如果将势能定义为“是其父节点的右孩子的节点总数”，我们可以构造如下包含 $n = 4q - 2$ 个节点的两棵斜堆 $H_1, H_2$（每棵各含 $2q - 1$ 个节点）：
- **斜堆 $H_1$**：右路径上有 $q$ 个节点，键值依次为 $1, 5, 9, \dots, 4q - 3$；给前 $q - 1$ 个右路径节点（$4i + 1$）各自挂一个**左叶子** $4i + 2$。此时 $H_1$ 共有 $q - 1$ 个右孩子；
- **斜堆 $H_2$**：右路径上有 $q$ 个节点，键值依次为 $3, 7, 11, \dots, 4q - 1$；给前 $q - 1$ 个右路径节点（$4i + 3$）各自挂一个**左叶子** $4i + 4$。此时 $H_2$ 也有 $q - 1$ 个右孩子。
- **合并分析**：
  1. **实际成本为 $\Theta(n)$**：两条右路径交错归并为长度为 $2q$ 的路径 $1 \to 3 \to 5 \to 7 \to \dots \to 4q - 1$，遍历整条路径耗时 $2q = \frac{n + 2}{2} = \Theta(n)$；
  2. **“右孩子总数”势能变化 $\Delta\Phi = 0$**：合并前两堆共有 $(q - 1) + (q - 1) = 2q - 2$ 个右孩子。合并后，归并路径上的 $2q - 1$ 个右孩子边全部被翻转到左侧成为了**左孩子**；**但是**，原本挂在前 $2q - 2$ 个右路径节点左侧的那 $2q - 2$ 个左叶子，在交换左右孩子后**全部被翻转到了右侧，变成了新的右孩子**！
  因此，合并后全堆依然有 $2q - 2$ 个右孩子（$\Delta\Phi = 0$），无法抵消 $\Theta(n)$ 的实际合并成本！而如果使用正确的**重节点势能函数**，合并前两条右路径上几乎全是重节点，合并后它们全部变成轻节点，势能大幅下降 $\Theta(n)$，完美抵消实际耗时。

---

**2. 从小到大依次插入 $1, 2, \dots, 2^k - 1$ 的树形结构（Exercise 4.4）**：
**两个说法均正确**（无论左偏堆还是斜堆，最终都会生成一棵有 $k$ 层的完美满二叉树 Perfect binary tree）！

- **对左偏堆的归纳证明**：
  当按递增顺序插入新最大键值时，新元素总是沿着当前堆的**最右侧路径**一直走到末端插入。对于完美满二叉树，每个节点的左右子树同构且 $\text{Npl}$ 相等，插入在最右端后会导致沿途祖先的右孩子 $\text{Npl}$ 比左孩子大 $1$，从而触发交换将填满的分支换到左侧，归纳可知每当节点数达到 $2^k - 1$ 时恰好填满 $k$ 层完美二叉树。
- **对斜堆的归纳证明**：
  斜堆每次插入最大键值时，沿着右路径一直走到末端挂接，并在回溯时将沿途所有祖先的左右子树交替翻转（左变右、右变左）。这相当于在一棵满二叉树下按二进制位反转顺序（Bit-reversal permutation）轮流向左右子树均匀分配新节点：每插入 $2^{k-1}$ 个新节点，恰好将第 $k$ 层的 $2^{k-1}$ 个叶子位置全部填满，故插入 $2^k - 1$ 个元素后必然形成一棵 $k$ 层完美满二叉树。

</details>
